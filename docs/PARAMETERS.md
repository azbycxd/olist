口径：步数使用任务级 termination.steps，multi 是编排汇总步数，不能等同单角色上限。token 含本题偏好设置/抽取、摘要、门禁等 Agent 调用，不含 eval_judge；任一模型调用缺 usage 时整题 token 留空。上下文峰值来自模型实际返回的 prompt_tokens，超应用上限的那次调用也计入；应用是在调用后检查，不能保证请求发送前不超限。

SQL 耗时是 tool_result 的端到端调用时间，包含 MCP、网络、SQL 执行及结果保存，不是数据库执行计划的纯执行时间。并发 SQL 的每题求和不是墙钟耗时；无 SQL 调用时和为零。结果行数从历史工具返回元数据提取；错误或被日志截断的返回没有行数时留空。每题行数最大值只取可见返回，可能低估缺失返回。SQL LIMIT 后的行数不能表示原始全量规模。

复核3新增 `MAX_SLEEP=5`（秒，来源类型：安全护栏），限制熔断冷却期间每次等待，确保周期性处理取消和截止；不改变30s冷却阈值。

## Step 12.3 B3 观测配置与告警

| 参数 | 默认 | 来源类型 | 用途 |
| --- | --- | --- | --- |
| OTEL_EXPORTER_OTLP_ENDPOINT | 空 | 预先固定 | OTLP HTTP collector基础地址；空时不创建exporter、不联网、不报错 |
| TOKEN_PRICE_INPUT | 空 | 预先固定 | 用户按供应商价格页填写，未命中缓存输入价，元/百万token |
| TOKEN_PRICE_CACHED_INPUT | 空 | 预先固定 | 用户按供应商价格页填写，命中缓存输入价，元/百万token |
| TOKEN_PRICE_OUTPUT | 空 | 预先固定 | 用户按供应商价格页填写，输出价，元/百万token |
| METRIC_DURATION_BUCKETS | .005,.01,.025,.05,.1,.25,.5,1,2.5,5,10,30,60,120,300 | 预先固定 | 秒；模型、SQL、队列等待直方图，覆盖既有10/60/300秒超时，未据实验调参 |

费用=(input-cached)×输入价+cached×缓存输入价+output×输出价，最后除以1000000。任一单价或必要usage缺失则费用留空，不视为0。缓存率只对供应商实际返回缓存字段的调用计算；未知不混进分母。供应商若没有该字段，报告注明“该供应商未返回”。/metrics费用为按当前配置价格计算的已知用量快照，不是账单或跨历史价格的结算金额。

以下规则仅文档，未接入告警系统；阈值均为预先固定运维起点/安全护栏，不来自holdout或参数搜索：

| 规则（PromQL） | 持续时间 | 阈值来源与含义 |
| --- | --- | --- |
| `olist_circuit_state == 2` | 0秒 | 安全护栏：沿用5次连续错误/30秒冷却，一开即告警 |
| `histogram_quantile(0.95, sum by(le)(rate(olist_queue_wait_seconds_bucket[5m]))) > 30` | 5分钟 | 预先固定：排队p95不宜超过默认300秒任务截止的10% |
| `sum(rate(olist_model_calls_total{error_class!="success"}[5m])) / clamp_min(sum(rate(olist_model_calls_total[5m])), 0.001) > 0.10` | 5分钟 | 预先固定：10%错误率；至少20次调用后判断，避免低流量噪声 |
| `up == 0` | 1分钟 | 安全护栏：抓取失败/进程不可达；按实际Prometheus job限制作用域 |

模型错误率规则部署时同时加 `sum(increase(olist_model_calls_total[5m])) >= 20`。任务计数是当前状态Gauge，model/token/lease/gate为事件累计Counter；删除历史事件会导致累计值重置，保留策略另属后续批次。标签只含固定状态、归一终止原因、错误分类、token种类和直方图le，不含task_id、user_id、SQL或供应商返回文本。

第2批复核后，Counter与直方图改由018迁移的metrics_rollup保存：事件插入和递增属于同一事务，counter只增不减，保留期清理不影响指标；上一段关于删除事件重置计数的描述仅适用于12.3原版本。/metrics不再扫描events。直方图边界由迁移固定为上表默认桶；已有汇总不能在运行中任意重分桶，更改边界需要新增迁移并明确历史数据处理，不能仅改环境变量。任务状态Gauge仍反映当前tasks。

容量说明：100个任务由4个worker各自串行处理时，排队p95约等于“任务数÷worker数×单任务耗时”（忽略启动开销和耗时分布的粗略容量关系，不是新测量数字）。这属于容量问题，不是故障；排队告警应结合worker数和单任务耗时解读。

## Step 12.3 B4 固定验收场景

以下是演练脚本的固定实验条件，不是服务新增配置，不做参数搜索。压测4 worker、100任务、100同时SSE及网络500ms/10%由本批指令预先指定；网络基线/故障各5任务、2 worker，丢失注入45秒后撤除，替身每次请求延迟1秒（数据库重启场景等待信号后4秒）、每次返回1000 tokens，均为预先固定的实验条件。池采样间隔50ms（压测）/100ms（其他）为预先固定观测粒度；实际循环含SQL/健康探测耗时。恢复时长和峰值是观测数据，不反向调整连接池、任务截止、重试或告警阈值。

Toxiproxy 2.13.0以packet_loss丢弃TCP数据块，loss_rate=0.1、correlation=0、toxicity=1；不等同于内核IP层丢包，也未测出精确实现丢失比例。网络场景同时代理MCP两个池，API/worker直连。测得的排队p95=89.463秒超过30秒告警起点，保留原阈值，不据本次结果调高。

## Step 12.4 C2 数据范围

`users.data_scope` 是管理员分配的用户权限，不是模型调参项（来源类型：安全护栏）；`{ALL}`表示不限，否则为巴西州代码数组。019迁移保留已有用户的ALL权限；新注册用户默认空数组，无业务数据权限。本地CLI新建用户、评测和全权限测试夹具显式设置ALL，已有同名CLI用户的限制不会被提升。`app.allowed_states`只在只读事务中SET LOCAL，连接归还后恢复；不提供模型可写的配置入口。
