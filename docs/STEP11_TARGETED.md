# Step 11 一次定向修复

本轮只缩减边界机制，不更改独立核查器、评分函数、题目、gold SQL 或知识库。固定协议为 D dev 两次、原边界题一次、新边界题一次；全部结束后停止调参。holdout 不重跑、不重新计分。

## 变更范围

维度值等值/IN 预检仍在 MCP 执行查询前完成，`DIMENSION_PRECHECK=true` 独立默认开启。未知值请求核对；有效值不增加提示或查询结果字段。`data_context`、`check_dimension` 保留为 MCP 内部能力，模型工具列表不增加这两项。

`BOUNDARY_GUARDS=true` 的候选配置只常驻一句：“缺少时间范围等关键条件时，请求澄清或明确写出所用假设。”代码解析问题日期，与实际购买日期覆盖比较；只有包含范围外日期时，追加一行覆盖说明。完整 profile、已知州列表、首尾月份和其余长规则不再注入。缺时间且没有假设/澄清的回答保留确定性澄清兜底。

日期判断支持数字年份、月/日、ISO 日期、季度、半年、同句继承年份，以及今年/去年/明年和本月/上月/下月；不调用模型。部分年度按全年区间识别越界，但不宣称解析器覆盖所有自然语言，也不以日期覆盖证明采集完备。普通范围内问题不收到时间覆盖元数据。

## 固定采用条件与回退

两次 D dev 必须分别达到 6/8，两组边界题必须分别达到 8/10，四项全部通过才采用候选配置。边界复核按原 expected 文本逐题检查保存回答；附加业务数字仍须直接 SQL 支持，格式误报、元数据 claim 问题单列。该复核由 Codex 完成，不是独立盲评，不额外调用评分模型。

若任一项未达到门槛，默认 `BOUNDARY_GUARDS=false`：恢复 Step 9 冻结的系统/工具提示、无边界额外上下文的路径、旧数字门禁格式识别，不执行新澄清兜底；边界增强作为可选开关保留。维度代码预检和 Step 10–11 的任务工程控制继续保留。这是分析行为配置回退，不撤销迁移、取消/超时/额度控制，也不把历史成绩冒充当前部署的新实测。

源码 ZIP、运行前协议、所有收据及日志名保留在 evidence。无论是否达到门槛，都不再追加调参或模型运行。

### D 仍失败的原因

- 两轮 D02：下降金额符号/字段契约不一致；第二轮还有把跨 SQL 的值拼成单行对象、重复同一事实字段导致矛盾的问题。
- 第二轮 D04：按季度行对象返回 avg_days，未使用公开要求的 q1_days/q2_days，实际查询数值正确仍未满足事实字段契约；短日期和换算常量也有门禁误替换。
- 两轮 D06：核心金额在判分容差内，但额外阈值/跨查询结论未获直接证据支持；两轮还误把问题要求的全部订单换成知识库的排除状态口径，不能把数值命中等同口径正确。
- 两轮 D07：核心事实正确；claim.text 中复购次数阈值没有作为 SQL 结果列，独立核查不豁免。

回退只恢复已冻结的分析提示、工具接口和数字门禁路径，保留默认开启的维度预检及后台控制。没有另跑回退后的模型评测，也不宣称当前部署已经重新测得 Step 9 的成绩。可选增强有条件覆盖提示、澄清兜底和格式识别，但本轮数据显示不足以作为默认。
