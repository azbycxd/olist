# 仍未解决的失败与边界

本次 holdout 只执行一次三轮协议，保留全部失败；没有据这些错误修改提示、运行时、gold 或评分器。以下是冻结判定下的失败，区分业务数值、输出契约与证据绑定问题，不把所有失败统称为“算错”。[最终统计](FINAL_RESULTS.md)中的原始得分不改写。

## Holdout D09：跨查询行拼成一个结论对象

题目询问季度英文品类缺失的商品明细、金额和总行数，并解释内连接损失。首轮所需事实命中 3/3，但整题失败；后两轮通过，因此该题正确 2/3 次。

首轮的 SQL 确实计算了损失，并非模型自行计算：一份查询结果有 `inner_join_items` / `inner_join_price`，另一份有 `items_lost_by_inner_join` / `price_lost_by_inner_join`。模型把这四个字段拼进同一个行对象，引用两个 result_id。按照既定契约，一个对象必须完整来自同一 SQL 结果行；没有任何一行包含这组键，因此最后一个 claim 被独立核查器判为 `value_not_in_result`。

门禁约束报告正文数字，不会重构错误的 claim 对象，也不能用数值相近证明同一业务语义。数字有来源与结论绑定正确是两件事。未来可以改善模型遵循输出契约的能力，但本次没有根据 holdout 修改提示或放宽核查器。

来源：[首轮收据](../evidence/eval_step9-holdout-r1_20261017T104235Z_7648ab8d.summary.json)，日志 `eval_step9-holdout-r1_20261017T104235Z_7648ab8d.jsonl`；保存的 SQL、列名、结果行与原始输出见下方只读诊断证据。

## Holdout D11：语义相同的长表没有遵守事实字段契约

题目询问季度取消订单数和取消率，并要求说明是否能断言原因。三轮均计为失败，规定的关键事实命中均为 0/4。

公开要求的字段是 `q1_canceled`、`q2_canceled`、`q1_cancel_pct`、`q2_cancel_pct`。三轮却都输出 `quarter`、`canceled`、`cancel_pct` 的长表行。保存的 SQL 和报告数值与 gold 一致：取消数分别为 133、57；取消率四舍五入为 0.6271%、0.2853%。确定性评分器按规定字段定位事实，不进行长表到宽表的语义变换，所以不给事实命中分。这暴露了模型遵循公开输出字段的不足，也暴露了该自动评测契约对等价结构的敏感性；不能把此处的零命中解释为业务数值全错，也不能临时更换规则把它改判正确。

第三轮正文里自行增加的倍数被门禁退回，但 `claim.text` 的“2018 上半年”仍被独立数字扫描识别为一个未支持数值；门禁只重写正文，元数据并未被修改。这是日期识别与扫描范围的已知局限，不等于取消数据造假。第二轮还给出了未经查询验证的“Q2 数据可能不完整”假设；数字门禁不能验证这种文字判断。模型评分较高也不代表该说法已获人工认可。

来源：[首轮](../evidence/eval_step9-holdout-r1_20261017T104235Z_7648ab8d.summary.json)、[第二轮](../evidence/eval_step9-holdout-r2_20261017T104451Z_7e1a9d1a.summary.json)、[第三轮](../evidence/eval_step9-holdout-r3_20261017T104707Z_e9d273ef.summary.json)。原始日志分别为 `eval_step9-holdout-r1_20261017T104235Z_7648ab8d.jsonl`、`eval_step9-holdout-r2_20261017T104451Z_7e1a9d1a.jsonl`、`eval_step9-holdout-r3_20261017T104707Z_e9d273ef.jsonl`。
